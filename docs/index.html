AI evals fail upstream.

The painful part is not always the model output. It is the hidden rot in the test set: duplicate scenarios, leaked answers, vague rubrics, stale cases, missing provenance, and coverage that does not match production.

DUP
Repeated scenarios inflate confidence.

One support flow repeated six ways can look like broad coverage while narrowing the actual release signal.

LEAK
Reference docs can give away the answer.

Open-book and closed-book cases need to be clearly separated before scores become decision inputs.

RUB
Weak rubrics create noisy grades.

If a human cannot grade it consistently, the model judge probably should not be trusted either.

GOV
Missing metadata blocks auditability.

Source, owner, severity, last review date, and gating status turn examples into release evidence.

The report should tell you what to fix first.

Follow the repo

A release pipeline for eval quality.

GSD should sit beside your eval runner, not replace it. The job is to inspect the evidence before the score gets authority.

01 Import

JSONL first, then CSV, Promptfoo, DeepEval, Braintrust, and LangSmith exports.

02 Inspect

Duplicates, leakage, rubric health, metadata, coverage balance, and stale examples.

03 Score

Fitness and readiness computed from available signals with explicit caveats.

04 Report

Executive summary, issue table, actionability labels, and prioritized fix plan.

05 Gate

CI thresholds that fail unsafe eval changes before they reach release meetings.

The end-state is governance without ceremony.

AI teams should be able to answer: can this eval suite be trusted for this release, what broke, what needs human review, and what evidence is missing?

LOCAL
Private by default.

Run on local eval files, references, and sampled logs without sending sensitive test cases to a hosted dashboard.

HONEST
Caveats are product features.

GSD separates what can be diagnosed from the eval set alone from what requires docs, production traffic, run history, or domain judgment.

CI
Quality gates belong in the workflow.

Eval-set health should fail builds when leakage, ungradeable rubrics, or readiness thresholds cross the line.

Before a score becomes a launch argument, the eval set should survive inspection.

What GSD can become.

Source-of-truth correctness

Compare expected answers against product docs, policy pages, and changelogs to surface stale or unsupported reference answers.

Production representativeness

Compare eval intent coverage against anonymized production queries so teams can see what is missing or overrepresented.

Historical sensitivity

Use eval history to detect flaky cases, low-discrimination examples, judge noise, and release thresholds that no longer mean what they used to.
